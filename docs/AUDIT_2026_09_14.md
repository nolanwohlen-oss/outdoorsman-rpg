# Systems foundation audit — 14 September 2026

Scope: current simulation, UI, save/migration, tests, build scripts and delivery configuration, compared with DESIGN_GATE.md and the Outdoorsman RPG master framework v2. This is a source review and local automated validation, not proof of full game readiness or Android device performance.

## Corrected in this update

- Preserve existing ecology, condition, inventory and fishing records when migrating supported older saves. Do not reset previously implemented layers while adding newer ones.
- Validate the inventory format appropriate to each legacy schema before migration. Reject fractional, boolean and nonfinite numeric fields where integer state is required.
- Count only births actually admitted at population capacity. Limit migration to destination capacity before removing fish from the source.
- Preserve retained/released totals when re-rigging. Reject travel and re-rigging during an active encounter; provide cancellation so the player can recover. Check encounter location before hooking or landing.
- Increment retained totals only after storage accepts the catch. Failed capacity checks must leave the world unchanged.
- Check every environmental boundary along route previews, including time limits, rather than checking only departure and arrival.
- Update the phase/version display, remove the misleading fixed two-minute camp label, and refresh resource/condition displays as time advances.
- Detect copied truncation markers instead of banning ordinary Unicode punctuation. Reinstall a cached engine if its version probe fails. The local executable was truncated; extracting the cached archive restored execution.

## Verified

213 simulation assertions passed, including new schema 4–7 migration preservation, capacity rejection without partial mutation, fishing action isolation, and population conservation at capacity. Android export remains a separate CI gate; phone interaction needs device testing after installation.

## What is actually implemented

The kernel is separate from its touch UI, with a foreground-only 6:1 clock, scheduled events, save recovery, generic connected test zones, coarse environmental layers, population counts, basic player condition, a simplified fishing encounter and pooled inventory quantities. These provide a useful systems laboratory. They are not the full simulation described in the master framework.

## Remaining gaps and ordered gates

1. **Physical inventory next.** Replace pooled resource counters with versioned item definitions and persistent instances/stacks. Track stable IDs, quantity, physical mass, condition, location and ownership. Separate ration calories from item mass. Retained fish need species, actual mass, catch time and condition. Add finite containers and explicit transfer/use/discard operations. Preserve old saves through documented migrations; never silently invent species for historical pooled fish.
2. **Explicit fish outcomes.** A fish remains a resource until the player chooses an available use. Processing, cooking, bait preparation and consumption must be separate transactions with game-time and resource costs. Do not automatically convert every catch into food or calories. Sale is later, when an economy exists.
3. **Fishing causality.** Add actual tackle and equipment state, species-specific body sizes, suitability-driven encounters, action duration and player decisions. Current timed encounters and broad random weights are scaffolding; they must not become the final behavior model.
4. **Camping and condition.** Add water treatment, fire/fuel, shelter, rest and food processing against inventory contracts. Distinguish energy from exertion stamina. Replace arbitrary condition rates with documented, bounded causal models before claiming realism.
5. **Ecology fidelity.** Current counts cannot represent individual animals, biomass or behavioral histories. Add the required population/organism representation and harvest accounting before richer encounters. The conservation fix does not reconstruct already-corrupted historical counters.
6. **Scenario gates before 3D.** Test full catch/store/process/use loops, save recovery across each version, capacity and cancellation failures, long simulation runs, and interrupted/background actions on Android. Then build the dedicated map and 3D presentation against the same authoritative simulation contracts.

## Explicit limits

Route search currently favors fewest links, not necessarily minimum travel time, and does not search all alternative routes around changing environmental closures. Synthetic weather/tides and five scalar condition values remain test models. Legacy saves exceeding current capacity are rejected rather than silently losing items; an explicit recovery/migration policy is still needed. There are no individual fish records, full equipment system, container access model, spoilage, crafting, combat, economy or complete RPG progression yet.

Monetization stays deferred until final release. Retain the generic map until the foundation gates pass. Future work should add targeted invariant and integration tests instead of treating a growing assertion count as proof of complete simulation fidelity.
